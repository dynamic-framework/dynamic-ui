## Icons

The `DIcon` component is a versatile icon component. It can render icons from four different sources.

Passing an **SVG/React component** directly as the `icon` prop always renders that component: the resolution below applies only to a **string** `icon`, which is resolved in this order of priority:

1. **`iconRegistry`** — a custom map of `name -> SVG component` configured on `DContextProvider`. A match replaces the string with its component.
2. **[Lucide Icons](https://lucide.dev)** — the default and recommended source. Pass the PascalCase name of any [Lucide icon](https://lucide.dev/icons/) (e.g. `"User"`, `"Home"`, `"Settings"`).
3. **Legacy icon fonts** — Bootstrap-style class-based fonts, used as a fallback when the string doesn't match a registry entry or a Lucide icon name.

The `materialStyle` flag is the exception to that order: when it's `true`, every string `icon` is rendered as Material-style icon-font content and Lucide is never consulted. `iconRegistry` still wins, because a registry match turns the string into a component before that check.

If a string resolves to none of the above and no icon font family is configured, `DIcon` renders a `"?"` placeholder and logs a console warning.

### Lucide Icons (default)

No configuration is required. Just use the PascalCase icon name:

### Custom SVG Registry (`iconRegistry`)

The `DContextProvider` accepts an `iconRegistry` prop: a `Record<string, IconComponent>`, where `IconComponent` is `ComponentType<SVGProps<SVGSVGElement>>`. This lets you plug in your own SVG icon components (e.g. a shared design-system icon set) and reference them by name, just like Lucide icons.

**Important:** `iconRegistry` only works with SVG React components — it does **not** work with icon-font syntax (Bootstrap classes, Material icon names, Font Awesome, etc.). If you need custom icon fonts, use the `icon` object on `DContextProvider` (see below) instead.

<Source
  code={`
import type { SVGProps } from 'react';
import { DContextProvider, DIcon } from '@dynamic-framework/ui-react';

const MyIcons = {
  Logo: (props: SVGProps<SVGSVGElement>) => (
    <svg viewBox="0 0 24 24" {...props}>
      <path d="..." />
    </svg>
  ),
};

<DContextProvider iconRegistry={MyIcons}>
  <DIcon icon="Logo" />
</DContextProvider>
  `}
  language="jsx"
/>

<Unstyled>
  <ExampleIconRegistry />
</Unstyled>

Note that names not found in the registry (like `"User"`) still fall through to Lucide, since resolution order is preserved.

You can also pass an SVG component directly as the `icon` prop, without registering it:

### Legacy Icon Fonts (Bootstrap / Material style)

When a string `icon` isn't found in `iconRegistry` and doesn't match a Lucide name, `DIcon` falls back to class-based icon fonts. They are also used for every string `icon` when `materialStyle` is `true`, which skips the Lucide lookup entirely. This is configured via the `icon` object on `DContextProvider`:

- `familyPrefix`: The prefix for the icon class (e.g., `bi-` for Bootstrap).
- `familyClass`: The class for the icon family (e.g., `bi` for Bootstrap icons).
- `materialStyle`: A boolean flag that determines how the icon is rendered. If `true`, the icon name is rendered as the content of the tag (Material Icons style). If `false`, the icon is rendered via a CSS class (Bootstrap/Font Awesome style).

<Source
  code={`
<DContextProvider
  icon={{
    familyClass: 'bi',
    familyPrefix: 'bi-',
    materialStyle: false,
  }}
>
  <DIcon icon="user" />
</DContextProvider>
  `}
  language="jsx"
/>

<Unstyled>
  <ExampleBootstrapIcons />
</Unstyled>

#### Material Style Flag

This flag comes in handy when you have icon fonts that need to be included as the content of the tag. Keep in mind that it applies to every string `icon` in its scope, so Lucide names are not resolved while it's enabled.

The following examples show the output of the `DIcon` component with and without the `materialStyle` flag.

## Accessibility

Icons are **decorative by default**: every render path emits `aria-hidden="true"`,
so an icon never adds noise to the accessibility tree. This matters most for the
legacy icon-font paths, where the ligature name is the element's text content and
a screen reader would otherwise read it out loud — `<i class="d-icon material-symbols-outlined">home</i>`
announcing "home" next to your own label.

You do not need to wrap `DIcon` in a hidden container. Inside a control that
already carries its own accessible name — a `DButton` with a visible label, a
`DButtonIcon` with its native `aria-label` — this is all you need:

<Source
  code={`
<DButtonIcon icon="Trash2" aria-label="Delete item" />
  `}
  language="html"
/>

For the rare icon that is the only carrier of meaning, give it a name with
`ariaLabel`. That renders `role="img"` and drops the default `aria-hidden`:

<Source
  code={`
<DIcon icon="CircleAlert" ariaLabel="Payment overdue" />
  `}
  language="html"
/>

`ariaHidden` is an explicit escape hatch. It is not symmetric with `ariaLabel`:
`ariaHidden` wins over a name, because hiding is absolute, while
`ariaHidden={false}` next to an `ariaLabel` is not a conflict — both expose the
icon, so the name is kept.

Avoid `ariaHidden={false}` on its own: it exposes an unnamed graphic to assistive
technology, which is the one state worse than hiding the icon. Non-production
builds warn when you do.

Note that `DIcon` names *itself*. An icon-only control still needs its own name
on the control — `DButtonIcon` takes the native `aria-label`, and without it the
button has no accessible name no matter how the icon is configured.

## Example Usage

#### Bootstrap Icons

```jsx
<DContextProvider
  icon={{
    familyPrefix: 'bi-',
    familyClass: 'bi',
    materialStyle: false,
  }}
>
  <DIcon icon="user" />
</DContextProvider>
```

#### Font Awesome Icons

To use Font Awesome icons, configure the `DContextProvider` as follows:

```jsx
<DContextProvider
  icon={{
    familyPrefix: 'fa-',
    familyClass: 'fa-solid',
    materialStyle: false,
  }}
>
  <DIcon icon="user" />
</DContextProvider>
```

#### Material Icons

To use Material icons, configure the `DContextProvider` as follows:

```jsx
<DContextProvider
  icon={{
    familyPrefix: '',
    familyClass: 'material-symbols-outlined',
    materialStyle: true,
  }}
>
  <DIcon icon="user" />
</DContextProvider>
```
