# Date Picker

A field and a calendar, both built here. `react-datepicker` is gone, and with
it the badge that used to sit at the top of this page saying the component was
an abstraction that "does not cover all the features of the original library" —
there is no original library any more, so there is nothing to not cover.

What the grid does is documented under
**Design System › Components › Calendar**, which is the same `DCalendar` this
component renders. Everything below is about the field.

## What changed in 3.0

The props were `Omit<DatePickerProps, …>` with twelve names subtracted: a
public surface nobody chose, where every prop the library happened to have was
part of this design system's API whether there was an answer for it or not.
They are now written out, and these ones are gone:

| Prop | Why |
|---|---|
| `showTimeSelect`, `showTimeSelectOnly`, `minTime`, `maxTime` | Replaced by `showTimeInput`, which renders the platform's own `type="time"` — keyboard-accessible and localised, which a hand-rolled column of half-hour strings never was. |
| `value` | Overrode the text in the field independently of the date: two sources of truth for one thing. The field renders `selected` through `dateFormat`. |
| `showTwoColumnMonthYearPicker`, `showFullMonthYearPicker` | Layout of the month grid, which the calendar now settles from how much room it has. |
| `showPopperArrow`, `showPreviousMonths`, `showDisabledMonthNavigation` | Implemented by the library, not by us — they were passed straight through. The replacements are: no arrow (the panel is anchored, not tethered), `monthsShown` for more than one month, and a disabled nav button rather than a hidden one. |
| `selectsDisabledDaysInRange` | A range could be drawn across days the calendar refuses. It cannot now. |
| `formatHeaderDate` | The header reads its names from `Intl` with the given `locale`. |
| `holidays` | `highlightDates` already means "days worth pointing at". |

`locale` is a BCP 47 string — `"es"`, `"pt-BR"` — not a `date-fns` locale
object. Every name in the calendar comes from `Intl`, which is in the browser,
so no locale data ships.

## The field does not accept typing

It is `readOnly`, as it has been since 2.x: the date is chosen in the grid.
`dateFormat` decides what the field SHOWS, and it understands the usual
tokens — `dd/MM/yyyy`, `MMMM`, `h:mm aa`. Text in single quotes is literal, so
`d 'de' MMMM` works.

## CSS variables

The calendar's own tokens are listed under
**Design System › Components › Calendar**. The panel is laid out with
`--df-calendar-gap`, and the field is a `DInput` — its tokens are under
**Input**.
