# Toast

![Shield Badge](https://img.shields.io/badge/Abstraction%20Component-4848b7)

The toast pattern combines two pieces: a **`DToastContainer`** component (the render target) and the **`useDToast`** hook (the dispatcher).
Both are built here. `react-hot-toast` is gone: the wrapper spent its length
undoing the library's choices — every toast went through `toast.custom()`
because the built-in markup was not ours, its `visible` flag had to be
translated into rendering `null`, and its container positioned itself with
inline styles the stylesheet then fought. What was actually used of it was a
list, six placements and a timer.

The region is now Bootstrap's own `.toast-container`, so the stack is dressed
by the same `--bs-toast-*` variables as the toast itself.

## Prerequisites

Before calling `useDToast`, two things must be present in the component tree:

1. **`DContextProvider`** — provides the icon map used by `DToast` for close and status icons.
2. **`DToastContainer`** — the portal where toasts are rendered. Place it once near the root of your app.

```
DContextProvider
├── <YourApp>          ← useDToast() → toast("Hello!")
└── <DToastContainer>  ← renders the notification portal
```

<Source
  code={`
import {
  DContextProvider,
  DToastContainer,
} from '@dynamic-framework/ui-react';

export function App() {
  return (
    <DContextProvider>
      {/* your app content */}
      <DToastContainer placement="top-end" />
    </DContextProvider>
  );
}
`}
  language="tsx"
  dark
/>

## `useDToast`

Call `useDToast` inside any component that is a descendant of `DContextProvider`.
It returns a single `toast` function.

<Source
  code={`const { toast } = useDToast();`}
  language="tsx"
  dark
/>

### Return value — `toast` function

| Parameter | Type | Required | Description |
|-----------|------|----------|-------------|
| `data` | `ToastData \| ReactNode` | ✅ | Toast content. Pass a `ToastData` object to use the default `DToast` layout, or any `ReactNode` for fully custom content. |
| `options` | `DToastOptions` | — | `id`, `duration` and `placement` for this one toast. |

**Returns** `string` — the toast id. Pass it to the `dismiss` the hook also
returns, or reuse it in a later `toast()` call to update that toast in place
rather than stacking a second one.

The hook returns `dismiss` and `dismissAll` alongside `toast`. Closing a toast
from outside it used to mean importing `react-hot-toast` and calling the
library's own `dismiss`, so the escape hatch was a third party's API.

<Source
  code={`const { toast, dismiss, dismissAll } = useDToast();`}
  language="tsx"
  dark
/>

## `ToastData`

Fields used when dispatching a toast with the default `DToast` layout.

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `title` | `string` | ✅ | Main text displayed in the toast. |
| `description` | `string` | — | Optional secondary text. When present, activates the header + body layout with a timestamp row. |
| `timestamp` | `string` | — | Timestamp string shown in the header (e.g. `"just now"`). Only visible when `description` is set. |
| `icon` | `string` | — | Icon name from the active icon set in `DContextProvider`. Shown before the title. |
| `closeIcon` | `string` | — | Overrides the default close icon from the context icon map. |
| `color` | `ComponentStateColor` | — | Applies the `toast-{color}` CSS modifier class (e.g. `"success"`, `"danger"`, `"warning"`, `"info"`). |
| `closeLabel` | `string` | — | Accessible name of the close button. Defaults to `"Close"`; pass the text in the app's language. |

`role` is gone. Every `DToast` used to carry `role="alert" aria-live="assertive"`,
and a live region inserted at the same moment as its content is frequently not
announced at all — the technology has to be watching the element before the
change happens, so the announcement came and went depending on timing.
`DToastRegion` owns it now: one `role="status" aria-live="polite"` region per
corner, rendered for the container's lifetime and empty between toasts. A toast
that genuinely must interrupt is a dialog.

## `DToastContainerProps`

Props accepted by `DToastContainer`.

| Prop | Type | Default | Description |
|------|------|---------|-------------|
| `placement` | `ToastPlacement` | `'bottom-center'` | Where toasts go when they do not name a placement. One of `top-start`, `top-center`, `top-end`, `bottom-start`, `bottom-center`, `bottom-end`. |
| `reverseOrder` | `boolean` | `false` | When `true`, new toasts appear at the bottom of the stack instead of the top. |
| `portal` | `boolean` | `true` | Renders into `document.body`. A region is `position: fixed`, and a fixed element inside an ancestor with a `transform`, a `filter` or `will-change` is positioned against THAT ancestor rather than the viewport — any animated wrapper above the container would pin the toasts to the middle of it. Turn it off for a test or a Storybook frame that needs the markup in place. |

`containerClassName`, `containerStyle`, `toastOptions` and `gutter` are gone:
they were all ways of reaching into a third party's markup. The region is ours
now, so it is themed like every other component.

| Variable | Element | Description |
|----------|---------|-------------|
| `--bs-toast-zindex` | `.toast-container` | Stacking order of the region. Bootstrap's own. |
| `--bs-toast-spacing` | `.toast-container` | Gap between stacked toasts — what `gutter` used to set in pixels. |
| `--bs-toast-container-inset` | `.toast-container` | Distance from the region to the edge of the viewport. |

### Custom content

Pass any `ReactNode` as the first argument for fully custom content.

This used to take a render function and hand it the library's own toast object —
an `id` and a `visible` flag the component had to translate into rendering
`null`. Both were bookkeeping leaking into a consumer's component: the container
decides what is mounted, and a toast that wants to close itself uses
`<DToastDismiss />`, which reads which toast it is in from context.
