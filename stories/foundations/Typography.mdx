# Typography Foundations

Dynamic Framework standardizes typography on top of Bootstrap 5 using the Jost typeface, a clear size scale, semantic text colors, and helpful utilities for weight, line-height, wrapping, and truncation.

<br />

### Type scale

Three families, each named for what it is rather than numbered:

| | |
|---|---|
| **Body** | `.df-fs-body` · `.df-fs-body-sm` · `.df-fs-body-xs` |
| **Headings** | `.df-fs-heading-1` … `.df-fs-heading-6`, or the element itself |
| **Display** | `.df-display-1` … `.df-display-6`, and `.df-fs-display-N` for the size alone |

The heading classes `.df-h1` … `.df-h6` carry the whole treatment — family,
weight, leading — so an element can LOOK like a heading without being one:
`<p class="df-h3">` where the document already has its h3.

<div className="df-flex df-flex-col df-gap-2 df-mt-2 df-mb-4">
  <div className="df-display-1">Display 1</div>
  <div className="df-display-4">Display 4</div>
  <h1>Heading H1</h1>
  <h3>Heading H3</h3>
  <p className="df-h1 df-m-0">Heading utility (.df-h1)</p>
  <p className="df-h4 df-m-0">Heading utility (.df-h4)</p>
  <p className="df-fs-body df-m-0">Body — 16px (.df-fs-body)</p>
  <p className="df-fs-body-sm df-m-0 df-text-muted">Small — 14px (.df-fs-body-sm)</p>
  <p className="df-fs-body-xs df-m-0 df-text-muted">Extra small — 12px (.df-fs-body-xs)</p>
</div>

**On `body-xs`.** It was called `caption` — a purpose, in a series otherwise
made of sizes. The step below `sm` was therefore unfindable by anyone reaching
for "extra small", which is how most people ask for it. Same 12px, same tighter
leading; only the name changed. `df-fs-caption` no longer exists.

```css
.df-fs-body     { font-size: var(--df-text-body-font-size); }      /* 16px */
.df-fs-body-sm  { font-size: var(--df-text-body-sm-font-size); }   /* 14px */
.df-fs-body-xs  { font-size: var(--df-text-body-xs-font-size); }   /* 12px */
```

Every one resolves through a `text.*` role, so a client retunes the scale by
overriding one role rather than every class that used it.

### Semantic text colors

Use `.text-{token}` with semantic states and extended palettes:
- Tokens: Primary, Success, Warning, Danger, Info, Secondary, Light, Dark
- Shades: `{25|50|100|200|300|400|500|600|700|800|900}` for background tints: `.bg-{token}-{shade}`
- Light variants are intended for dark backgrounds

### Font weight and line-height

- Line-height utilities: `.lh-1`, `.lh-sm`, `.lh-base`, `.lh-lg`

  <p className="df-fw-normal df-my-1">Normal weight</p>

  <p className="df-lh-normal df-my-1">Line-height base</p>
  <p className="df-lh-loose df-my-1">Line-height lg</p>

```css
.lh-lg   { line-height: var(--df-line-height-loose); }
```

### Flow spacing

`p`, lists, `blockquote`, `pre`, `figure` and `table` carry a bottom margin
from `text.body`. **Headings do not.**

```css
p, ul, ol, dl, blockquote, figure, pre, table {
  margin-block: 0 var(--df-text-body-margin-block-end);
}
```

That split is deliberate and it is worth knowing which half you are in.

**Why running text keeps a margin.** A CMS body, a Liquid template, a block of
terms pasted into a modal — the author writes `<p>` and has no class to hang
spacing on. Zeroed and never restored, it runs together, and the design tokens
a client hands over describe spacing on those elements.

**Why headings do not.** A heading's spacing depends on what it opens, which
the element cannot know. Most frameworks leave it to an opt-in `prose` scope
for the same reason.

**But "undecided" is not a state a browser offers.** The UA stylesheet has
already decided — in `em`, which resolves against the font size *we* set. So
headings are zeroed in the reset, the same line Tailwind's Preflight and
Bootstrap's Reboot both carry. What those frameworks leave to `prose` is what
comes *after* the zero.

Removing the rule without zeroing is what it looks like:

| | font-size | UA margin | result |
|---|---|---|---|
| `h1` | 48px | `0.67em` | 32px |
| `h6` | 16px | `2.33em` | **37px** |

The smallest heading ends up the most widely spaced thing on the page. In
DevTools the UA rule shows either way — struck through when something overrode
it, which is the only signal that it lost. `css:verify` fails the build if any
element the UA gives a margin is left without an author answer.

The consequence, so it is not a surprise: a heading between two paragraphs sits
`--df-text-body-margin-block-end` below the one above it and **flush against
the one below**. If that is wrong for your content, the heading's spacing is
yours to set — which is the point of leaving it undecided.

<div className="df-p-4 df-mb-4" style={{ border: '1px solid var(--df-border-muted)', borderRadius: 'var(--df-radius-md)' }}>
  <p>A paragraph before the heading.</p>
  <h3>A heading</h3>
  <p>And the paragraph it introduces, flush against it.</p>
</div>

Two more things:

- Adjacent margins **collapse**, so stacked blocks take the larger of the two
  rather than their sum — the browser's own model.
- The library's content slots — a modal body, a card body — trim the first and
  last child, so text sits flush against the container's padding instead of
  adding to it.

`css:flow` fails the build if a component renders a flow element without
deciding its margin.

### Text wrapping and truncation

- Balanced wrapping: `.text-wrap-balance`
- Normal wrapping: `.text-wrap-normal`; Force wrap: `.text-wrap-wrap`
- Truncation by lines (responsive): `.text-truncate-{1..6}`

<div className="df-flex df-flex-col df-gap-2 df-mt-2 df-mb-4" style={{ maxWidth: 360 }}>
  <p className="text-wrap-balance">
    Balanced wrapping strives for visually even lines for better readability across varying widths.
  </p>
  <p className="text-wrap-wrap">
    Force wrapping when you need long identifiers or URLs to break across lines gracefully.
  </p>
  <p className="text-truncate-3">
    Long text that will be truncated to three lines. Long text that will be truncated to three lines. Long text that will be truncated to three lines. Long text that will be truncated to three lines with additional content to ensure overflow beyond three lines in typical widths. This sentence adds even more content so the ellipsis appears reliably across viewports. Yet another clause to extend the content further.
  </p>
</div>

```css
/* Text wrap utility values */
.text-wrap-balance { text-wrap: balance; }
.text-wrap-normal  { text-wrap: normal; }
.text-wrap-truncate{ text-wrap: truncate; }
.text-wrap-wrap    { text-wrap: wrap; }

/* Truncate uses CSS vars and -webkit-line-clamp under the hood */
```

### Dark mode and hover variants for text

- Dark mode variant: `.dark:text-{token}` adapts text color in dark contexts
- Hover variant: `.hover:text-{token}` provides interactive feedback on text

```html
<a class="df-text-default df-hover:text-danger">Hover to see danger color</a>
<div class="df-text-default df-dark:text-success">Text turns success in dark</div>
```
