# Design Tokens

Dynamic Framework builds on Bootstrap 5 and exposes a robust set of CSS variables and Sass tokens to craft brand themes. Prefer overriding CSS variables at runtime for theming, and use Sass variables for build-time defaults when shipping a custom bundle. Official documentation is available at https://docs.modyo.com.

<br />

## Principles
- Scope overrides: use `:root` for global themes and a zone (`[data-bs-theme="<name>"]`) for a subtree with its own colors. A zone needs more than the global theme; see [Zones](#zones).
- Colors that have an RGB triplet (`--bs-<name>-rgb`) travel in it. Their variables without `-rgb` (`--bs-primary`, `--bs-body-bg`) are wrappers computed from the triplet: on `:root` set the triplet, not the wrapper; a zone sets both (see [Zones](#zones)). Colors without a triplet, such as `--bs-border-color`, take the value directly.
- Change variables, not classes: utilities and components read from CSS variables; overriding variables updates the whole system consistently.
- Validate contrast: ensure WCAG AA for text/background, borders, and focus rings.

<br />

### Core variables (what to override)
These variables drive components and utilities; override them to theme typography, colors, spacing, borders, and shadows consistently.

#### Typography
Key CSS variables:
- Family and body: `--bs-body-font-family`, `--bs-body-font-size`, `--bs-body-line-height`
- Heading sizes: `--bs-fs-1` … `--bs-fs-6`
- Display sizes: `--bs-fs-display-1` … `--bs-fs-display-6`
- Small text: `--bs-fs-small`; line-heights: `--bs-lh-sm`, `--bs-lh-base`, `--bs-lh-lg`
- Heading line-height: `--bs-heading-line-height`

`--bs-fs-N` is an alias of `--bs-rfs-fs-N`. Steps 1 to 4 are fluid: the library computes them with RFS as a value that grows with the viewport below 1200px and a fixed size from 1200px on. Steps 5 and 6 are a fixed size at every width and have no desktop cap. Override `--bs-rfs-fs-N`; a stylesheet loaded after Dynamic's already wins at every width. To keep the same behavior (fluid below 1200px, capped on desktop), set the fluid value on `:root` and the desktop size of steps 1 to 4 in the same media query:

```css
:root {
  --bs-body-font-family: "Jost", system-ui, sans-serif; /* or your brand font */
  --bs-body-font-size: 1rem; /* base body size */
  --bs-rfs-fs-1: calc(1.425rem + 2.1vw); /* h1, fluid below 1200px */
  --bs-rfs-fs-2: calc(1.375rem + 1.5vw);
  --bs-rfs-fs-5: 1.25rem; /* steps 5 and 6 are not fluid */
  --bs-rfs-fs-6: 1rem;
}

@media (min-width: 1200px) {
  :root {
    --bs-rfs-fs-1: 3rem; /* h1 on desktop */
    --bs-rfs-fs-2: 2.5rem;
  }
}
```

`npm run theme:expand` generates the fluid value and the 1200px block from a single size per step.

#### Typography variables (headings and display)
Components read the `--bs-fs-*` aliases; the value lives in the RFS variable each one points to, which is the one to override:

| Components read | Override | Fluid below 1200px |
|---|---|---|
| `--bs-fs-1` … `--bs-fs-4` | `--bs-rfs-fs-1` … `--bs-rfs-fs-4` | yes; set the desktop cap in `@media (min-width: 1200px)` |
| `--bs-fs-5`, `--bs-fs-6` | `--bs-rfs-fs-5`, `--bs-rfs-fs-6` | no |
| `--bs-fs-display-1` … `--bs-fs-display-6` | `--bs-rfs-display-1` … `--bs-rfs-display-6` | yes, same media query |
| `--bs-fs-small` | `--bs-rfs-fs-small` | no |

`--bs-heading-line-height` has no alias and is overridden directly.

#### Usage examples
```html
<h1 class="h1">Heading 1 (.h1)</h1>
<h6 class="h6">Heading 6 (.h6)</h6>
<div class="display-1">Display 1</div>
<div class="display-6">Display 6</div>
<p class="fs-1 m-0">.fs-1</p>
<p class="fs-6 m-0">.fs-6</p>
<p class="small m-0">Small text (.small)</p>
```

#### Color system
Dynamic’s palettes expose base tokens and extended shades.
- Base semantic tokens: `--bs-primary`, `--bs-success`, `--bs-warning`, `--bs-danger`, `--bs-info`, `--bs-secondary`, `--bs-light`, `--bs-dark`
- Extended shades by state: e.g., `--bs-primary-25`, `--bs-primary-50`, …, `--bs-primary-900`
- Text/background/border subtles: `--bs/{token}-text-emphasis`, `--bs/{token}-bg-subtle`, `--bs/{token}-border-subtle`
- Body defaults: `--bs-body-color`, `--bs-body-bg`, links: `--bs-link-color`, `--bs-link-hover-color`

Override the **triplets**, not the wrappers. The library declares every role and body color twice: the triplet that holds the value (`--bs-primary-rgb: 32, 104, 213`) and a wrapper computed from it (`--bs-primary: rgb(var(--bs-primary-rgb))`). Buttons, utilities such as `.bg-primary` and `.text-bg-primary`, and anything with opacity read the triplet; a hex value on `--bs-primary` changes only what reads the wrapper, so the brand shows up halfway.

```css
:root {
  /* Role: the base triplet and its ramp (500 is an alias of the base), as generated by theme:expand */
  --bs-primary-rgb: 10, 106, 232;
  --bs-primary-25-rgb: 243, 248, 254;
  --bs-primary-50-rgb: 231, 240, 253;
  --bs-primary-100-rgb: 206, 225, 250;
  --bs-primary-200-rgb: 157, 195, 246;
  --bs-primary-300-rgb: 108, 166, 241;
  --bs-primary-400-rgb: 59, 136, 237;
  --bs-primary-500-rgb: var(--bs-primary-rgb);
  --bs-primary-600-rgb: 8, 85, 186;
  --bs-primary-700-rgb: 6, 64, 139;
  --bs-primary-800-rgb: 4, 42, 93;
  --bs-primary-900-rgb: 2, 21, 46;
  /* Text of .text-bg-primary: the one that contrasts with the new base */
  --bs-primary-text-bg-color: var(--bs-white);

  /* Body */
  --bs-body-color-rgb: 46, 52, 56;
  --bs-body-bg-rgb: 255, 255, 255;
}
```

- The ramp steps are literal triplets, so changing only `--bs-primary-rgb` leaves `--bs-primary-100` and the rest of the ramp at the default brand.
- Links follow the role: `--bs-link-color-rgb` points to `--bs-primary-rgb` and `--bs-link-hover-color-rgb` to its 700 step, so they only need an override to use a different color.
- `.text-bg-<role>` reads its text from `--bs-<role>-text-bg-color`, resolved for the default role, in every role but `secondary`. A role redefined to a light tone needs a dark value there (`var(--bs-gray-700)`). `.text-bg-secondary` has no such variable: it paints `--bs-secondary-700` on `--bs-secondary-50`, so it follows the secondary ramp.
- `.btn-<role>` keeps the white or dark text resolved for the default palette, so pick a base that contrasts with it (this example is 4.95:1 against white) or override the button text colors.
- `npm run theme:expand` takes one color per role and writes its base triplet, the ramp of the roles that have one (25 to 900, with 500 as an alias of the base; all but `light` and `dark`) and `--bs-<role>-text-bg-color` for every role but `secondary`, which reads its ramp. `npm run theme:validate` checks the result, contrast included.

#### Palette variables (25–900)
Each role with a ramp (`primary`, `secondary`, `success`, `info`, `warning`, `danger`) exposes 11 triplets. Step 500 is `var(--bs-<role>-rgb)`, so a rebrand sets the base and the other 10:
```css
:root {
  --bs-primary-rgb: /* R, G, B */;
  --bs-primary-25-rgb: /* R, G, B */; --bs-primary-50-rgb: /* R, G, B */; --bs-primary-100-rgb: /* R, G, B */;
  --bs-primary-200-rgb: /* R, G, B */; --bs-primary-300-rgb: /* R, G, B */; --bs-primary-400-rgb: /* R, G, B */;
  --bs-primary-600-rgb: /* R, G, B */; --bs-primary-700-rgb: /* R, G, B */; --bs-primary-800-rgb: /* R, G, B */;
  --bs-primary-900-rgb: /* R, G, B */;
  /* Same shape for success, info, warning, danger and secondary. */
}
```
`light` and `dark` have no ramp: only `--bs-light-rgb` and `--bs-dark-rgb`.

A dark area of the page, such as a header or a banner, is a subtree with its own palette: see [Zones](#zones).

### Spacing scale
Override spacing globally or create theme scopes:
```css
:root {
  --bs-ref-spacer-4: 16px;  /* baseline */
  --bs-ref-spacer-6: 24px;
  --bs-ref-spacer-8: 32px;
  --bs-ref-spacer-12: 48px;
}
[data-bs-theme="compact"] {
  --bs-ref-spacer-6: 20px; /* tighter */
}
```

#### Borders, radius, shadows, focus
- Radius: `--bs-border-radius`, `--bs-border-radius-sm`, `--bs-border-radius-lg`, `--bs-border-radius-xl`, `--bs-border-radius-xxl`, `--bs-border-radius-pill`
- Border: `--bs-border-width`, `--bs-border-style`, `--bs-border-color`, `--bs-border-color-translucent`
- Shadows: `--bs-box-shadow`, `--bs-box-shadow-sm`, `--bs-box-shadow-lg`
- Focus ring: `--bs-focus-ring-width`, `--bs-focus-ring-opacity`, `--bs-focus-ring-border-color`, `--bs-focus-ring-color`

## Component tokens (examples)
Many component styles are derived from the core variables, but some expose specific tokens:
- Buttons: variant tokens are generated off theme colors; customize via core color variables and (optionally) component CSS vars like --bs-btn-border-radius
- Alerts/Badges: read semantic tokens and bg-subtle/border-subtle
- Forms: validation colors map to --bs-form-valid-color/border-color, --bs-form-invalid-color/border-color

```css
/* Optional per-component tweak */
:root {
  --bs-btn-border-radius: var(--bs-border-radius-lg);
}
```

## Zones
A zone is a subtree with its own palette: `[data-bs-theme="<name>"]` on any element, such as a dark header or a branded banner in a light app. Dynamic is compiled with Bootstrap's color modes turned off (`$enable-dark-mode: false`), so there is no global dark scheme to switch on: a dark area is a zone, and it inherits from `:root` everything it doesn't declare. The `dark:` utilities do follow the system preference, but each one only changes the element it is applied to; they don't redefine tokens and are not a dark scheme (see [Dark Utilities](?path=/docs/design-system-examples-dark-utilities--docs)).

**Declare the triplet and the wrapper.** A custom property is computed on the element that declares it and inherited already resolved: the library declares `--bs-body-color: rgb(var(--bs-body-color-rgb))` on `:root`, so a zone that only changes the triplet doesn't move anything that reads the wrapper.

```css
/* ❌ Only the triplets: the wrappers keep the :root values, and the zone looks like the rest of the page */
[data-bs-theme="night"] {
  --bs-body-bg-rgb: 17, 24, 39;
  --bs-body-color-rgb: var(--bs-white-rgb);
  color: var(--bs-body-color);
  background-color: var(--bs-body-bg);
}

/* ✅ The triplet and its wrapper */
[data-bs-theme="night"] {
  --bs-body-bg-rgb: 17, 24, 39;
  --bs-body-bg: rgb(17, 24, 39);
  --bs-body-color-rgb: var(--bs-white-rgb);
  --bs-body-color: rgb(var(--bs-white-rgb));
  color: var(--bs-body-color);
  background-color: var(--bs-body-bg);
}
```

**A minimal zone.** The zone declares the body and surface colors as triplet and wrapper, the variables that have no triplet (`--bs-border-color`, `--bs-heading-color`), and the link colors as triplet and wrapper: plain links read the triplet, `.btn-link` reads the wrapper. The library applies `--bs-body-bg` and `--bs-body-color` on `body`, so the zone paints itself with `color` and `background-color`. Components with their own colors get a block in the zone:

```css
:root {
  --bs-body-bg-rgb: 248, 249, 251;
  --bs-body-color-rgb: var(--bs-gray-900-rgb);
  --bs-border-color: rgb(var(--bs-gray-100-rgb));
  --bs-secondary-bg-rgb: var(--bs-gray-50-rgb);
  --bs-tertiary-bg-rgb: var(--bs-gray-25-rgb);
}

[data-bs-theme="night"] {
  --bs-body-bg-rgb: 17, 24, 39;
  --bs-body-bg: rgb(17, 24, 39);
  --bs-body-color-rgb: var(--bs-white-rgb);
  --bs-body-color: rgb(var(--bs-white-rgb));
  --bs-secondary-bg-rgb: var(--bs-gray-800-rgb);
  --bs-secondary-bg: rgb(var(--bs-gray-800-rgb));
  --bs-tertiary-bg-rgb: var(--bs-gray-900-rgb);
  --bs-tertiary-bg: rgb(var(--bs-gray-900-rgb));
  --bs-secondary-color-rgb: var(--bs-white-rgb);
  --bs-secondary-color: rgba(var(--bs-white-rgb), .75);
  --bs-tertiary-color-rgb: var(--bs-white-rgb);
  --bs-tertiary-color: rgba(var(--bs-white-rgb), .5);
  --bs-emphasis-color-rgb: var(--bs-white-rgb);
  --bs-emphasis-color: rgb(var(--bs-white-rgb));
  --bs-heading-color: rgb(var(--bs-white-rgb));
  --bs-border-color: rgba(var(--bs-white-rgb), .15);
  --bs-link-color-rgb: var(--bs-primary-300-rgb);
  --bs-link-color: rgb(var(--bs-primary-300-rgb));
  --bs-link-hover-color-rgb: var(--bs-primary-200-rgb);
  --bs-link-hover-color: rgb(var(--bs-primary-200-rgb));
  color: var(--bs-body-color);
  background-color: var(--bs-body-bg);
}

[data-bs-theme="night"] .nav {
  --bs-nav-link-color: rgb(var(--bs-white-rgb));
  --bs-nav-link-hover-color: rgb(var(--bs-primary-200-rgb));
}

[data-bs-theme="night"] .btn-primary {
  --bs-btn-color: rgb(var(--bs-gray-900-rgb));
  --bs-btn-bg: rgb(var(--bs-primary-200-rgb));
  --bs-btn-border-color: rgb(var(--bs-primary-200-rgb));
  --bs-btn-hover-color: rgb(var(--bs-gray-900-rgb));
  --bs-btn-hover-bg: rgb(var(--bs-primary-100-rgb));
  --bs-btn-hover-border-color: rgb(var(--bs-primary-100-rgb));
  --bs-btn-active-color: rgb(var(--bs-gray-900-rgb));
  --bs-btn-active-bg: rgb(var(--bs-primary-300-rgb));
  --bs-btn-active-border-color: rgb(var(--bs-primary-300-rgb));
}

[data-bs-theme="night"] .list-group {
  --bs-list-group-color: rgb(var(--bs-body-color-rgb));
  --bs-list-group-bg: transparent;
  --bs-list-group-action-color: rgb(var(--bs-body-color-rgb));
  --bs-list-group-border-color: var(--bs-border-color);
}
```

**What a zone doesn't change without its own block.** The text, background and links of the zone follow it, and so do `.text-body-secondary` and `.popover-header`, because the zone declares the wrappers they read (`--bs-secondary-color`, `--bs-secondary-bg`). `.alert-<role>` and `.text-bg-<role>` keep their `:root` colors on their own background. Without a block of their own:
- `.nav` links and `.list-group` items keep the `:root` text color, dark on the dark zone. `.nav-pills` reads its own variables, which don't reach from `.nav`, so it needs a separate block.
- `.btn-<role>` keeps its `:root` colors, because the zone doesn't change the role triplets.
- `.form-control`, `.form-select` and `.modal` keep their light surface and inherit the zone's text: white on white. Give each one a block with a readable text color or a dark surface.

`npm run theme:expand` writes a zone, its `color` and `background-color`, and the component blocks from the `zones` section of a theme file. `npm run theme:validate` measures each zone against its own background and assumes that background for everything inside it, so it doesn't catch a component with its own surface, such as `.form-control`: check those in the preview (`npm run theme:preview`). The full reference is in `scripts/theme/README.md`.

## Theming workflow (recommended)
1. Define brand color palette (primary/success/warning/danger/info/secondary + tints 25–900).
2. Set typography: body family/size, heading/display scales, small text, line-heights.
3. Tune spacing scale and component gaps using --bs-ref-spacer-*.
4. Adjust radius, borders, shadows, focus tokens for personality and accessibility.
5. Theme dark or branded subtrees as [zones](#zones); there is no global dark scheme. Validate contrast.
6. Verify utilities (fs-*, display-*, text-*, bg-*, border-*) reflect your overrides.

## Bootstrapping a theme (copy-paste starter)
There are two ways to start, and they don't mix: copying both would duplicate declarations.

- **Generated:** `npm run theme:expand` writes a complete stylesheet from a theme file. From one color per role it writes the base triplet, the ramp of the roles that have one (25 to 900, with 500 as an alias of the base; all but `light` and `dark`) and `--bs-<role>-text-bg-color` for every role but `secondary`, which reads its ramp; it also writes body colors, font family and radius, which the theme file requires, and only the type scale steps the file lists (`typography.scale` is optional). Global additions (spacing, shadows) go in the file's `root` section, which is emitted in the root block at every width. A subtree with its own palette goes in `zones` (see [Zones](#zones)). See `scripts/theme/README.md`.
- **Hand-written:** the starter below. It has no role colors; copy each role's full block (as in [Color system](#color-system)) or take it from the `theme:expand` output.
```css
/* Global theme */
:root {
  /* Typography */
  --bs-body-font-family: "Jost", system-ui, sans-serif;
  --bs-body-font-size: 1rem;
  --bs-heading-line-height: 1.2;
  --bs-rfs-fs-small: .875rem;

  /* Color tokens: triplets, not hex on the wrappers */
  --bs-body-bg-rgb: 255, 255, 255;
  --bs-body-color-rgb: 46, 52, 56;
  /* Role colors: each role's full block, see the note above */

  /* Spacing */
  --bs-ref-spacer-4: 16px;
  --bs-ref-spacer-6: 24px;

  /* Radius/Shadows */
  --bs-border-radius: .5rem;
  --bs-box-shadow: 0 2px 8px rgba(0,0,0,.08);
}
```
